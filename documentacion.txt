DOCUMENTACIÓN DEL CÓDIGO: SISTEMA DE RIEGO AUTOMATIZADO
================================================================================

================================================================================
1. DESCRIPCIÓN GENERAL
================================================================================

Este programa implementa un sistema de riego automatizado sobre una placa Arduino.
El sistema monitorea tres variables físicas y actúa en consecuencia:

  - Temperatura y humedad ambiental  -> Sensor DHT22 (pin 2)
  - Humedad del suelo                -> Sensor analógico (A0)
  - Peso del depósito de agua        -> Celda de carga + HX711 (pines 6 y 5)

El actuador principal es un motor/bomba conectado al pin digital 10.


================================================================================
2. LIBRERÍAS UTILIZADAS
================================================================================

  #include <DHT.h>
  #include "HX711.h"

  - DHT.h  : Permite leer el sensor DHT22 (temperatura y humedad del aire).
  - HX711.h: Controla el amplificador/conversor HX711, usado para leer la
             celda de carga (báscula).


================================================================================
3. CONSTANTES Y VARIABLES GLOBALES
================================================================================

3.1 SENSOR DE TEMPERATURA
-------------------------

  #define Type DHT22
  int dhtPin = 2;
  DHT HT(dhtPin, Type);
  const float UMBRAL_TEMPERATURA = 45.0;

  - Type: define el modelo de sensor como DHT22.
  - dhtPin = 2: el sensor está conectado al pin digital 2.
  - HT: objeto de la clase DHT que representa al sensor.
  - UMBRAL_TEMPERATURA = 45.0: si la temperatura alcanza o supera 45 °C,
    se activa la alerta térmica.

3.2 SENSOR DE HUMEDAD DEL SUELO Y MOTOR
---------------------------------------

  const int pinSensorHumedad = A0;
  const int pinMotor = 10;
  const int umbralHumedad = 45;

  int valorSensor = 0;
  int porcentajeHumedad = 0;

  - pinSensorHumedad = A0: entrada analógica donde se conecta el sensor de
    humedad de suelo.
  - pinMotor = 10: salida digital que controla la bomba
    (HIGH = encendida, LOW = apagada).
  - umbralHumedad = 45: umbral en porcentaje. Si la humedad supera el 45 %,
    se considera suelo suficientemente húmedo.
  - valorSensor y porcentajeHumedad: almacenan la lectura cruda (0-1023) y su
    conversión a porcentaje.

3.3 ESTADO DE ALERTA TÉRMICA
----------------------------

  bool alertaTermica = false;

  Bandera global que indica si la temperatura superó el umbral. Se actualiza en
  cada ciclo y es consultada por el control de la bomba.

3.4 BÁSCULA (CELDA DE CARGA)
----------------------------

  const int LOADCELL_DOUT_PIN = 6;
  const int LOADCELL_SCK_PIN  = 5;
  HX711 scale;
  const float FACTOR_CALIBRACION = -209.9429;
  const float UMBRAL_PESO_BAJO = 25.0;

  - LOADCELL_DOUT_PIN = 6 y LOADCELL_SCK_PIN = 5: pines de datos y reloj del
    HX711.
  - scale: objeto HX711 para leer la celda de carga.
  - FACTOR_CALIBRACION = -209.9429: factor obtenido empíricamente que convierte
    las lecturas crudas del ADC en gramos. El signo negativo compensa la
    orientación física de la celda.
  - UMBRAL_PESO_BAJO = 25.0: si el peso medido es menor a 25 g, se emite una
    alerta de "llenar de agua".


================================================================================
4. FUNCIÓN setup()
================================================================================

Se ejecuta una sola vez al arrancar. Realiza:

  1. Inicialización del puerto serie a 9600 baudios (Serial.begin(9600)).
  2. Inicialización del DHT22 (HT.begin()).
  3. Configuración del pin del motor como salida y se asegura de que esté
     apagado (digitalWrite(pinMotor, LOW)).
  4. Impresión de mensajes de arranque con los umbrales configurados.
  5. Inicialización del HX711:
     - scale.begin(...): configura los pines.
     - delay(1000): espera a que el amplificador se estabilice.
     - scale.set_scale(FACTOR_CALIBRACION): aplica el factor de calibración.
     - delay(2000) + scale.tare(): tarado, se toma la lectura actual como cero
       (se debe retirar todo peso antes).
     - delay(2000): espera final antes de comenzar el loop.


================================================================================
5. FUNCIONES DEL SISTEMA
================================================================================

5.1 leerTemperatura()
---------------------

  float leerTemperatura()

  PROPÓSITO: leer la temperatura y la humedad ambiental del DHT22.

  FUNCIONAMIENTO:
    1. Llama a HT.readTemperature().
    2. Si el resultado es NAN (lectura fallida), imprime un error y retorna NAN.
    3. Si es válida, imprime la temperatura en °C.
    4. Adicionalmente lee HT.readHumidity() y, si es válida, imprime la humedad
       ambiental.

  RETORNO: la temperatura en °C, o NAN si falló la lectura.

  NOTA: el DHT22 tiene una frecuencia de muestreo limitada (~0.5 Hz). El
  delay(2000) del loop principal es adecuado para este sensor.


5.2 verificarTemperatura(float temperatura)
-------------------------------------------

  PROPÓSITO: actualizar la bandera alertaTermica y reportar el estado.

  FUNCIONAMIENTO:
    1. Si temperatura no es NAN, actualiza:
         alertaTermica = (temperatura >= UMBRAL_TEMPERATURA)
       Si la lectura es NAN, conserva el estado anterior de la bandera
       (no la cambia).
    2. Imprime en el monitor serie:
       - Si hay alerta:
           ">> Temperatura ALTA (X C) -> Motor forzado ENCENDIDO"
       - Si no hay alerta:
           ">> Temperatura normal"


5.3 controlBomba()
------------------

  PROPÓSITO: decidir el estado del motor según humedad del suelo y alerta
  térmica.

  FUNCIONAMIENTO PASO A PASO:

    1. Lectura del sensor de humedad:

         valorSensor = analogRead(pinSensorHumedad);           // 0 a 1023
         porcentajeHumedad = map(valorSensor, 1023, 0, 0, 100); // inversión
         porcentajeHumedad = constrain(porcentajeHumedad, 0, 100);

       - analogRead devuelve 0-1023.
       - map(..., 1023, 0, 0, 100) invierte la escala: lecturas altas
         (suelo seco) -> 0 %, lecturas bajas (suelo húmedo) -> 100 %.
         Esto asume que el sensor entrega mayor voltaje cuando el suelo está
         seco (configuración típica de sensores resistivos/capacitivos).
       - constrain garantiza que el porcentaje quede en el rango 0-100.

    2. Impresión de los valores leídos.

    3. Lógica de decisión (prioridad):

       +-------------------------------+--------------------------+------------------------------------------------------------+
       | Condición                     | Acción del motor         | Mensaje                                                    |
       +-------------------------------+--------------------------+------------------------------------------------------------+
       | alertaTermica == true        | ENCENDIDO (HIGH)         | "Motor ENCENDIDO (por temperatura alta, humedad ignorada)" |
       | porcentajeHumedad > umbral   | APAGADO (LOW)            | "Motor apagado (por humedad)"                              |
       | En cualquier otro caso        | ENCENDIDO (HIGH)         | "Motor encendido"                                          |
       +-------------------------------+--------------------------+------------------------------------------------------------+

       RAZONAMIENTO DE LA LÓGICA:
       - La alerta térmica tiene prioridad absoluta: si hace demasiado calor,
         se enciende el riego aunque el suelo ya esté húmedo (para enfriar).
       - Si no hay alerta térmica y el suelo está suficientemente húmedo
         (> 45 %), la bomba se apaga.
       - Si no hay alerta térmica y el suelo está seco (<= 45 %), la bomba se
         enciende.

       OBSERVACIÓN IMPORTANTE: los mensajes de la primera y tercera rama están
       invertidos respecto a la acción real. En la rama
       "porcentajeHumedad > umbralHumedad" se hace digitalWrite(pinMotor, HIGH)
       (enciende) pero se imprime "Motor apagado". Lo mismo ocurre en la rama
       else: se hace LOW (apaga) pero se imprime "Motor encendido". La lógica de
       hardware parece correcta, pero los mensajes están intercambiados. Se
       recomienda corregir los textos para evitar confusión durante el
       monitoreo.


5.4 leerBascula()
-----------------

  PROPÓSITO: leer el peso del depósito y alertar si está bajo.

  FUNCIONAMIENTO:
    1. Verifica que el HX711 esté listo (scale.is_ready()).
    2. Lee el peso con scale.get_units(10) (promedio de 10 muestras para
       estabilidad).
    3. Aplica abs() para obtener el valor absoluto (evita negativos por ruido).
    4. Si el peso es menor a 1 g, lo fuerza a 0 (elimina deriva del cero).
    5. Imprime el peso con un decimal.
    6. Si el peso es menor a UMBRAL_PESO_BAJO (25 g), imprime:
         ">>> ALERTA: LLENAR DE AGUA (peso bajo) <<<"
    7. Si el HX711 no responde, imprime un mensaje de error de conexión.


================================================================================
6. FUNCIÓN loop()
================================================================================

Ciclo principal que se repite indefinidamente cada 2 segundos:

  void loop() {
    Serial.println("======= LECTURAS =======");
    float temperatura = leerTemperatura();
    verificarTemperatura(temperatura);
    controlBomba();
    leerBascula();
    Serial.println("-----------------------");
    delay(2000);
  }

SECUENCIA DE EJECUCIÓN:

  1. Imprime un separador de cabecera.
  2. Lee la temperatura del DHT22.
  3. Evalúa la alerta térmica (actualiza alertaTermica).
  4. Controla la bomba usando la humedad del suelo y el estado de alerta
     térmica (por eso la alerta se calcula antes).
  5. Lee el peso del depósito de agua.
  6. Imprime un separador de cierre.
  7. Espera 2 segundos antes del siguiente ciclo.

NOTA: El orden es importante: verificarTemperatura() debe ejecutarse antes de
controlBomba() para que la bandera alertaTermica esté actualizada cuando el
control de la bomba la consulte.

================================================================================
10. CONSIDERACIONES Y RECOMENDACIONES
================================================================================

  1. MENSAJES INVERTIDOS EN controlBomba(): los textos de las ramas de humedad
     están intercambiados respecto a la acción real del motor. Conviene
     corregirlos para que el monitoreo serie sea coherente con el hardware.

  2. FRECUENCIA DEL DHT22: el sensor DHT22 requiere al menos ~2 s entre
     lecturas. El delay(2000) del loop es adecuado, pero si se reduce habría
     que aumentar el intervalo de lectura del DHT.

  3. CALIBRACIÓN DE LA BÁSCULA: el FACTOR_CALIBRACION debe recalibrarse si se
     cambia la celda de carga o su montaje mecánico. El procedimiento típico es
     colocar un peso conocido y ajustar el factor.

  4. TOLERANCIA A FALLOS DEL DHT: si el DHT falla (NAN), la bandera
     alertaTermica conserva su último valor. Esto es intencional (fail-safe: si
     antes había alerta, se mantiene), pero podría considerarse un
     comportamiento más explícito.

  5. SENSOR DE HUMEDAD: la función map(1023, 0, 0, 100) asume una relación
     lineal inversa. Sensores capacitivos suelen requerir calibración en seco y
     en agua para ajustar los extremos reales.

  6. SIN HISTÉRESIS: la bomba puede encenderse/apagarse repetidamente si la
     humedad oscila alrededor del 45 %. Se podría añadir una banda de histéresis
     (p. ej., encender a 40 % y apagar a 50 %) para evitar ciclos rápidos.

  7. SEGURIDAD DEL MOTOR: no hay límite de tiempo de funcionamiento continuo de
     la bomba. Para riegos prolongados podría añadirse un temporizador máximo.


================================================================================
11. RESUMEN EJECUTIVO
================================================================================

El sistema lee cada 2 segundos la temperatura/humedad ambiental, la humedad del
suelo y el peso del depósito. Con esos datos:

  - ENCIENDE LA BOMBA si hay alerta térmica (>= 45 °C) o si el suelo está seco
    (<= 45 % de humedad).
  - APAGA LA BOMBA si el suelo está suficientemente húmedo y no hay alerta
    térmica.
  - EMITE UNA ALERTA si el depósito pesa menos de 25 g (nivel bajo de agua).

Toda la información se reporta por el monitor serie a 9600 baudios para su
supervisión.
